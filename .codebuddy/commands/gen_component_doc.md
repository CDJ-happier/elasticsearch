# 生成 Elasticsearch 组件文档

请为指定的 Elasticsearch 类生成详细的技术文档，并整合到 `docs/learning/general_programming_style/` 目录结构中。

## 执行步骤

### 1. 查找源码
- 使用 Glob 查找目标类：`**/{CLASS_NAME}.java`
- 使用 Read 读取类的完整实现
- 查找并阅读相关测试文件（`**/*{CLASS_NAME}Test*.java`）
- 搜索类的引用位置，了解实际使用场景

### 2. 分析类的设计
分析以下关键点：
- **设计意图**：这个类要解决什么问题？
- **核心机制**：关键字段、核心方法、状态管理
- **依赖关系**：继承、实现、组合了哪些类
- **使用场景**：在源码中如何被使用
- **设计模式**：使用了哪些设计模式

### 3. 生成文档

使用 Write 工具创建 `docs/learning/general_programming_style/{CLASS_NAME}.md`，包含以下结构：

#### 必需章节（按顺序）：

##### 1. 一句话总结
```markdown
## 一句话总结

**`{CLASS_NAME}` 是...**
```
精炼概括核心功能和定位

##### 2. 问题背景（Why）
```markdown
## 问题背景（Why - 为什么需要它？）

### 现有方案的不足
### 典型痛点场景
### 不解决的后果
```
说明为什么需要这个组件

##### 3. 组件介绍（What）
```markdown
## 解决方案（What - 它是什么？）

### 核心定位
### 核心特性
### 与相关模块的对比（表格）
### 设计理念
```

##### 4. 使用指南（How）
```markdown
## 使用指南（How - 如何使用它？）

### 基本使用流程（带代码）
### 典型场景示例（至少3个）
### 核心 API 说明
### 使用注意事项
```

##### 5. 实现原理（How it works）
```markdown
## 实现原理（How it works - 它如何实现？）

### 核心数据结构
### 关键实现机制
### 状态转换图（ASCII art）
### 并发控制机制（如适用）
### 设计亮点
```

##### 6. 完整使用实例
```markdown
## 完整使用实例

### 实例 1：[场景名称]
### 实例 2：[场景名称]
```

##### 7. 最佳实践
```markdown
## 最佳实践

### ✅ 推荐做法
### ❌ 常见陷阱
### 解决方案
```

##### 8. 组件关系
如果有，则实现：
```markdown
## 与其他组件的关系

- 依赖关系
- 协作关系
- 使用场景对比
```

##### 9. 总结
```markdown
## 总结

### 适用场景
### 不适用场景
### 关键要点
### 与其他工具的对比（表格）（如果有）
```

#### 可选章节（根据组件特点添加）：
- 线程模型和执行器
- 内存管理技巧
- 性能考虑
- 设计模式解析
- 异常处理策略
- 超时控制机制

### 4. 更新主索引

使用 Read 读取 `docs/learning/general_programming_style.md`，然后使用 Edit 在"组件列表"中添加：

```markdown
### [{CLASS_NAME}](general_programming_style/{CLASS_NAME}.md)
一句话描述组件功能。
- 关键特性1
- 关键特性2
- 关键特性3
```

按逻辑关系或字母顺序排序。

### 5. 验证完整性
- ✅ 检查所有必需章节是否完整
- ✅ 验证代码示例语法正确
- ✅ 确认 mermaid 图表格式正确
- ✅ 检查表格对齐
- ✅ 验证链接有效性

## 格式要求

### 代码示例
- 使用 ```java 代码块
- 包含必要的注释
- 展示完整的上下文
- 使用 ✅ 和 ❌ 标记正确/错误示例

示例：
```java
// ❌ 错误：不捕获异常
ActionListener.delegateFailure(listener, (l, data) -> {
    riskyOperation(data);  // 可能抛出异常
});

// ✅ 正确：使用 delegateFailureAndWrap
ActionListener.delegateFailureAndWrap(listener, (l, data) -> {
    riskyOperation(data);  // 异常会被捕获
});
```

### 表格格式
使用清晰的对比表格，比如：
```markdown
| 特性 | 组件A | 组件B | 组件C |
|------|-------|-------|-------|
| 特性1 | ✅ 支持 | ❌ 不支持 | ⚠️ 部分支持 |
| 特性2 | 描述文字 | 描述文字 | 描述文字 |
```

### mermaid图标
使用mermaid绘制可视化内容，提升可理解度，比如flowchat, sequence diagram, class diagram, gantt, etc.

### 标记和强调
- **重要概念**：使用 **粗体**
- 代码/类名：使用 `反引号`
- 注意事项：使用 ⚠️ 或 > 引用块
- 正确示例：✅
- 错误示例：❌
- 部分支持：⚠️


## 输出要求

1. **完整性**：确保所有必需章节都完整
2. **准确性**：代码示例必须基于真实源码
3. **清晰性**：使用简洁的中文，配合代码和图表
4. **实用性**：提供真实可用的代码示例
5. **一致性**：与现有文档保持格式和风格统一
